# نظام GroceryPOS — مرجع النظام

**آخر تحديث:** 2026-11-13  
**الغرض:** مرجع موحّد لفكرة النظام ونطاقه وتصميمه وحالته. يحل هذا الملف محل ملفات المتطلبات والتحليل والتصميم السابقة. سكربت قاعدة البيانات يبقى مرجعًا مستقلاً في [`GroceryPOS_Database.sql`](./GroceryPOS_Database.sql).

## 1. فكرة النظام

نظام مكتبي لإدارة بقالة، يجمع نقطة البيع والمخزون والمشتريات والعملاء والموردين والحسابات في قاعدة SQL Server مركزية. صُمم للعمل في محل واحد مع إمكانية اتصال عدة أجهزة كاشير بالشبكة المحلية. الواجهة عربية واتجاهها من اليمين إلى اليسار، مع دعم قارئ الباركود والطباعة في مراحل لاحقة.

الهدف التشغيلي هو تسجيل كل حركة بيع وشراء ومخزون ونقد بدقة، مع معرفة سببها ومستخدمها، ومنع تكرار المستندات أو ظهور أرصدة سالبة نتيجة تزامن الأجهزة.

## 2. المستخدمون والصلاحيات

| الدور الابتدائي | المسؤوليات |
|---|---|
| المالك | الإعداد وإدارة المستخدمين والأدوار، الاطلاع على جميع البيانات والتقارير والنسخ الاحتياطي. |
| المدير | إدارة التشغيل والموافقة على العمليات الحساسة ومراجعة التقارير. |
| الكاشير | البيع والمرتجعات وعمليات الوردية والصندوق وفق الأذونات. |
| أمين المخزن | المنتجات والمشتريات والجرد وتسويات المخزون. |
| المحاسب | العملاء والديون والموردون والسداد والمصروفات والعملات والتقارير المالية. |

تُمنح الأذونات الدقيقة للأدوار، ثم تُربط الأدوار بالمستخدمين. إخفاء الزر في الواجهة ليس بديلاً عن فحص الإذن داخل خدمة العملية.

## 3. النطاق الوظيفي المستهدف

1. **الدخول والأمان:** تسجيل الدخول، تجزئة كلمات المرور مع Salt، قفل مؤقت لمحاولات الدخول الفاشلة، الأدوار والأذونات، الموافقات وسجل التدقيق.
2. **الكتالوج:** المنتجات والتصنيفات والوحدات والباركود وأسعار البيع والجملة وحالة النشاط والحد الأدنى للمخزون وتتبع الصلاحية.
3. **المخزون:** دفعات مشتريات وتواريخ صلاحية وحركة مخزون دائمة، صرف FEFO، التنبيهات والجرد والتسويات.
4. **المشتريات والموردون:** أوامر شراء، استلام وفواتير، دفعات المخزون، ديون الموردين وسدادها والمرتجعات.
5. **نقطة البيع:** إدخال بالباركود أو البحث، تعديل السلة والخصم، الدفع النقدي والمختلط والآجل، تعليق الفاتورة، الإلغاء والمرتجعات وإعادة الطباعة.
6. **العملاء والديون:** سقف ائتماني، سندات قبض، توزيع السداد على الفواتير وكشوف الحساب والأرصدة بحسب العملة.
7. **الورديات والصندوق:** الرصيد الافتتاحي لكل عملة، الحركات النقدية، العدّ والإغلاق والفرق والتقرير.
8. **العملات والمالية:** YER هي العملة الأساسية، وSAR وUSD عملتان إضافيتان افتراضيتان؛ أسعار صرف مؤرخة، مصروفات، وأرباح موحّدة بالعملة الأساسية.
9. **التقارير والإدارة:** المبيعات والأرباح والمخزون والديون، سجل التدقيق والنسخ الاحتياطي والإعدادات. تجهيز واجهات الطباعة والتقارير القابلة للتصدير جزء من النطاق المستهدف، لا من التنفيذ الحالي.

## 4. قواعد العمل المحورية

- الأرقام المالية `decimal` وليست `float`، ويُثبّت سعر الصرف داخل المستند لحظة تسجيله.
- تُحفظ الفاتورة أو السند وحركات المخزون والصندوق والدفتر ذات الصلة ضمن معاملة واحدة: الكل ينجح أو يُلغى.
- لا يُسمح بمخزون سالب. تُصرف الدفعات ذات الصلاحية بالأقرب انتهاءً أولًا (FEFO)، ويُمنع بيع المنتهي إلا بإذن خاص.
- لا تُحذف المستندات المالية أو حركات المخزون؛ التصحيح بقيود عكسية أو إلغاء موثق. الجداول المرجعية تُعطّل بدلاً من حذفها.
- رقم كل مستند فريد ومتسلسل. تُستخدم مفاتيح منع التكرار عند حفظ العمليات التي قد يعاد إرسالها.
- البيع بالأجل يخضع لسقف دين العميل، وتسجيل النقد يتطلب وردية مفتوحة.
- تُسجّل العمليات الحساسة مع المستخدم والوقت والقيم السابقة واللاحقة في سجل التدقيق.
- السداد يوزّع على الأقدم أولًا ما لم يختر المحاسب فاتورة بعينها. الدين يبقى بعملة الفاتورة ولا يعاد تقييمه تلقائيًا.

## 5. قاعدة البيانات

المرجع التنفيذي للمخطط والبيانات الأولية هو [`GroceryPOS_Database.sql`](./GroceryPOS_Database.sql). السكربت مخصص لـ SQL Server 2019 أو أحدث، ويتضمن قاعدة `GroceryPOS` والجداول والقيود والفهارس والمشغلات والإجراء `usp_GetNextDocumentNumber` وعروض التحقق وبيانات الأدوار والعملات والإعدادات. المخطط الحالي يحوي 46 جدولاً.

مجموعات الجداول الرئيسية:

- الهوية والأمان: المستخدمون والأدوار والأذونات وسجل التدقيق.
- الإعدادات والعملات وأسعار الصرف وتسلسلات المستندات.
- التصنيفات والوحدات والمنتجات ووحدات المنتج والباركود.
- الموردون والعملاء وأرصدة دفاترهم وقيودهم.
- أوامر وفواتير ومرتجعات المشتريات والدفعات وحركات المخزون والجرد والتسويات.
- الورديات وحركات الصندوق وفواتير البيع ومدفوعاتها ودفعات المخزون المرتبطة بالبيع والمرتجعات وسندات قبض العملاء.
- المصروفات وبنودها.

`vw_ProductStock` يعرض كميات الدفعات، و`vw_CustomerBalanceCheck` و`vw_SupplierBalanceCheck` يكشفان اختلاف الأرصدة المخزنة عن دفاتر الحركة. السكربت يحمي بعض السجلات من التعديل أو الحذف بمشغلات. تُراجع طريقة تشغيله قبل إعادة تشغيله على قاعدة قائمة؛ ليس سكربت ترقية.

## 6. البنية التقنية

### الحالة الحالية

- تطبيق Windows Forms واحد في `GroceryPOS.csproj` يستهدف **.NET Framework 4.8**.
- الوصول إلى البيانات يستخدم `System.Data.SqlClient` واتصالاً معرفاً في `App.config`.
- إعداد الجهاز المحلي الحالي يستخدم Windows Integrated Security إلى SQL Server على `localhost`.
- بيئة التطوير الحالية لديها SQL Server 2022 وقاعدة `GroceryPOS` مجهّزة بـ46 جدولاً.
- الملفات البرمجية الحالية مجمّعة في مشروع واحد؛ لم تُنشأ بعد طبقات Domain / Application / Infrastructure أو مشروع اختبارات مستقل.

### البنية المستهدفة على مراحل

الفصل بين واجهة WinForms، وخدمات التطبيق وقواعد العمل، والوصول إلى البيانات والطباعة والنسخ الاحتياطي. يفترض التصميم النظري تعدد المشاريع، لكن التطبيق لا يزال في مشروع واحد؛ لا يُعد هذا الفصل منجزًا.

## 7. قرارات وافتراضات التصميم

- النظام فرع واحد حالياً، ويعمل على Windows 10 أو أحدث؛ قاعدة البيانات المركزية على SQL Server 2019 أو أحدث.
- العملات الابتدائية YER وSAR وUSD. العملة الأساسية هي YER؛ أسعار الصرف تُدخل يدوياً ولا تُخمن.
- آلية تكلفة المخزون المختارة في مخطط التصميم والبيانات الأولية هي **المتوسط المرجح**، مع الاحتفاظ بتكلفة كل دفعة. ينبغي تثبيت هذا القرار في منطق الشراء والبيع والتقارير واختبار أثره المالي قبل احتساب الأرباح.
- الضريبة غير مفعّلة افتراضياً.
- نطاق الأداء المستهدف يصل إلى 7 أجهزة كاشير متزامنة؛ يلزم إثبات ذلك باختبارات التزامن قبل النشر، وليس بمجرد وجود القيود والفهارس.

## 8. ما هو منفّذ فعلاً

### منجز

- نقطة تشغيل تفتح إعداد المالك الأول أو شاشة تسجيل الدخول، ثم لوحة رئيسية.
- إعداد الاتصال بقاعدة البيانات المحلية.
- إنشاء المالك الأول بمعاملة واحدة، مع ربطه بدور المالك وتسجيل أثر الإنشاء.
- تجزئة كلمة المرور بـ PBKDF2-HMAC-SHA256، مع Salt عشوائي، و600,000 دورة، ومقارنة ثابتة الزمن.
- رفض الدخول للحساب غير النشط أو المقفل، وتسجيل المحاولات الفاشلة وقفل الحساب بحسب إعدادات قاعدة البيانات.
- تحميل أدوار وأذونات المستخدم بعد نجاح الدخول.
- كتالوج منتجات أولي: بحث بالاسم أو SKU أو الباركود، وعرض التصنيف والوحدة والسعر والكمية المتاحة والحد الأدنى وحالة الصلاحية.
- إضافة المنتج وتعديل بياناته الأساسية وأسعار وحدة البيع الأساسية، وتعطيله دون حذفه. التعديل يسجل القيم السابقة والجديدة في سجل التدقيق.
- إدارة التصنيفات الهرمية: إنشاء وإعادة تسمية التصنيف واختيار تصنيف رئيسي، والتفعيل والتعطيل دون حذف. يمنع تعطيل تصنيف رئيسي ما دامت له تصنيفات فرعية نشطة.
- إدارة وحدات البيع المتعددة لكل منتج: معامل التحويل إلى الوحدة الأساسية، باركود وسعر مفرق/جملة لكل وحدة، وحدة بيع افتراضية، وتفعيل الوحدة أو تعطيلها. لا تُحذف الوحدات المرتبطة بحركات؛ تتحول إلى غير نشطة.
- فرض أذونات `Products.View` و`Products.Manage` في الواجهة والخدمة. الوحدة الأساسية للمنتج القائم لا تتغير لتجنب تغيير دلالة المخزون.
- تعديل أسعار البيع يتطلب `Products.EditPrice`، منفصلاً عن إذن إدارة بيانات المنتج.
- إدارة المستخدمين: إنشاء الحسابات بكلمات مرور مجزأة، تعديل الأسماء واسم الدخول، إسناد الأدوار النشطة، وتفعيل الحسابات أو تعطيلها. تمنع الخدمة تعطيل الحساب الحالي أو إزالة آخر حساب نشط بصلاحية إدارة المستخدمين، وتسجل التعديلات في سجل التدقيق.
- إدارة الأدوار: إنشاء أدوار مخصصة، تعديل الأوصاف والصلاحيات، وتفعيل الأدوار المخصصة أو تعطيلها. أدوار النظام لا يمكن إعادة تسميتها أو تعطيلها؛ وتُرفض التغييرات التي تزيل صلاحية إدارة المستخدمين من جميع الحسابات النشطة.
- كلمات المرور: يُلزم المستخدمون الجدد بتغيير كلمة المرور المؤقتة عند أول دخول. يمكن للمستخدم تغيير كلمته بعد التحقق من الحالية، كما يستطيع مدير مخوّل تعيين كلمة مؤقتة جديدة لمستخدم آخر؛ يُطلب من المستلم تغييرها عند الدخول التالي. لا تُسجل كلمات المرور في سجل التدقيق.
- الموردون والمشتريات: إدارة الموردين وتعطيلهم دون حذف، واستلام فاتورة شراء متعددة الأصناف بعملة نشطة وسعر صرفها المؤرخ. حفظ الفاتورة وأسطرها ودفعات المخزون وحركاته ومتوسط تكلفة المنتجات ورصيد المورد ودفتره وسجل تدقيقها ضمن معاملة واحدة. تُرفض الوحدات أو المنتجات غير النشطة والدفعات المنتهية، ويُطلب تاريخ الصلاحية للمنتجات المتتبعة.
- تسجيل الأخطاء التقنية في `%LOCALAPPDATA%\GroceryPOS\logs\application.log` دون عرض تفاصيل قاعدة البيانات للمستخدم.

### غير منفّذ بعد

إنشاء وإدارة الشاشات والخدمات لبقية الوحدات: أوامر الشراء، سداد الموردين والمرتجعات، الجرد والتسويات، البيع والتحصيل، مرتجعات المبيعات، الورديات، العملات والمصروفات، التقارير، النسخ الاحتياطي والطباعة. لا توجد حالياً اختبارات آلية مستقلة أو نشر مهيأ لأجهزة أخرى.

## 9. خطة البناء المقترحة

1. إضافة اختبارات آلية مستقلة لمسارات الصلاحيات والكتالوج وكلمات المرور، ثم استكمال التحقق قبل التشغيل.
2. إكمال أوامر الشراء وسداد الموردين ومرتجعات المشتريات والجرد والتسويات، ثم إضافة اختبارات مستقلة.
3. بناء نقطة البيع والصرف FEFO والدفعات والدفع المختلط ومنع التكرار.
4. إضافة الورديات والصندوق والعملاء والديون والسداد والعملات والمرتجعات.
5. إضافة المصروفات والتقارير والتدقيق والنسخ الاحتياطي والطباعة.
6. اختبار الاستعادة والتزامن والصلاحيات والحالات المالية، ثم إعداد النشر والتدريب.

كل مرحلة يجب أن تحافظ على معاملات قاعدة البيانات، ودفاتر الحركة، والتدقيق، والصلاحيات؛ ولا تُعلن مكتملة قبل اختبار مسارات النجاح والفشل والتزامن ذات الصلة.
