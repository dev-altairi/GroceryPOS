# دليل الصيانة والتطوير

**آخر تحديث:** 2026-11-13  
**المرجع الوظيفي:** [`System-Overview.md`](./System-Overview.md)  
**مرجع المخطط:** [`GroceryPOS_Database.sql`](./GroceryPOS_Database.sql)

## 1. متطلبات بيئة التطوير الحالية

- Windows 10 أو أحدث.
- .NET Framework 4.8 Developer/Targeting Pack.
- Visual Studio 2022 أو .NET SDK مع MSBuild.
- SQL Server 2019 أو أحدث. بيئة التطوير الحالية تعمل على SQL Server 2022 المحلي.
- قاعدة `GroceryPOS` مجهزة من سكربت SQL المرجعي، ووجود بيانات الأدوار والوحدات والتصنيفات والإعدادات فيها.

لا يحتاج التطبيق إلى حزم NuGet خارجية في الحالة الحالية.

## 2. البناء وتشغيل التطبيق

من PowerShell:

```powershell
dotnet build .\GroceryPOS.sln --no-restore -p:GenerateResourceMSBuildArchitecture=x64
dotnet build .\GroceryPOS.sln --no-restore --configuration Release -p:GenerateResourceMSBuildArchitecture=x64
```

يحدد `GenerateResourceMSBuildArchitecture=x64` معمارية مضيف مهمة موارد MSBuild. بدونه قد يفشل SDK الحديث على هذا الجهاز بسبب طلب مضيف موارد x86.

الناتج التنفيذي:

- `GroceryPOS\bin\Debug\GroceryPOS.exe`
- `GroceryPOS\bin\Release\GroceryPOS.exe`

شغّل التطبيق تحت حساب Windows الذي يملك حق الاتصال بقاعدة البيانات. عند أول تشغيل، إذا لم يوجد مستخدم سوى حساب `system` المعطّل، تظهر شاشة إنشاء المالك. اختر كلمة مرور لا تقل عن 12 حرفاً؛ تُجزّأ قبل تخزينها. بعد ذلك يظهر تسجيل الدخول. لا يُحفظ اسم المستخدم أو كلمة المرور في ملف الإعدادات.

## 3. اتصال قاعدة البيانات

الإعداد الحالي في [`..\GroceryPOS\App.config`](../GroceryPOS/App.config) هو:

```text
Data Source=localhost;Initial Catalog=GroceryPOS;Integrated Security=True
```

على جهاز آخر أو خادم شبكة، غيّر `Data Source` إلى اسم الخادم/النسخة المناسبة واضبط صلاحيات SQL Server وحساب تشغيل التطبيق. لا تضع كلمة مرور إنتاج في الشيفرة أو في هذا المستودع. استخدم حساب قاعدة بيانات محدود الصلاحيات كما يوضح القالب المعلّق في نهاية سكربت SQL؛ الاستعادة تحتاج مساراً إدارياً منفصلاً.

التحقق من اتصال SQL Server بالأدوات المحلية:

```powershell
sqlcmd -E -S localhost -d GroceryPOS -Q "SELECT @@VERSION"
```

المشروع يتبع حالياً نمط WinForms في مشروع واحد. إذا أُضيفت طبقات أو مشاريع، حدّث الحل ومراجع المشاريع واختبارات البناء مع توثيق اتجاه الاعتماد.

شاشات الإعداد الأولي وتسجيل الدخول ولوحة التحكم وتغيير كلمة المرور والكتالوج ومحرر المنتج وإدارة التصنيفات ومحرر التصنيف ووحدات المنتج وإدارة الموردين ومحرر المورد وقائمة فواتير الشراء وتفاصيل الفاتورة منقولة إلى ملفات WinForms Designer. حُذف `Form1` الافتراضي غير المستخدم؛ يبدأ التطبيق بشاشة الإعداد الأولي أو تسجيل الدخول. عند تعديل عناصر هذه الشاشات، حدّث `*.Designer.cs` من المصمم واترك التحقق والأحداث في ملف الشيفرة المقابل. بقية الشاشات ما زالت تُنشئ عناصرها برمجياً، لذلك لم يكتمل دعم المصمم على مستوى النظام بعد.

## 5. قواعد يجب اتباعها عند إضافة وحدة

1. **الصلاحيات:** أضف فحص الإذن قبل إظهار الوظيفة في الواجهة، وأعد فحصه داخل خدمة الكتابة. لا تعتمد على إخفاء الزر وحده.
2. **SQL:** استخدم معاملات SQL ذات أنواع وأحجام صريحة، ولا تركّب مدخلات المستخدم داخل نص الاستعلام. أسماء الجداول الديناميكية لا تأتي من المستخدم.
3. **المعاملات:** أي عملية تغيّر أكثر من جدول مرتبط (مثل مستند ودفعات ودفتر أو صندوق) تُنفذ داخل Transaction واحدة، مع التراجع عند الفشل.
4. **الأثر:** لا تحذف السجلات المالية ولا حركات المخزون. استخدم حالات الإلغاء أو القيود العكسية وسجل `AuditLogs` بالقيم السابقة والجديدة.
5. **المرجع:** استخدم المفاتيح الأجنبية والقيود والفهارس القائمة؛ لا تضف طريقة ثانية لحساب المخزون أو الأرصدة دون توحيدها مع الجداول والعروض.
6. **المبالغ:** `decimal` مع الدقة المتوافقة مع SQL، وتثبيت سعر الصرف والتقريب وقت المستند.
7. **الأخطاء:** اعرض رسالة عربية موجزة وسجّل التفاصيل التقنية في سجل التطبيق. لا تخفِ الاستثناءات ولا تعتبر الفشل نجاحاً.
8. **التعطيل:** الجداول المرجعية تدعم `IsActive`؛ لا تحذف المنتج الذي قد يكون له مخزون أو سجل بيع.
9. **المعاملات الفريدة:** عند إنشاء مستندات، استخدم التسلسل ومفتاح منع التكرار المعرّفين في مخطط قاعدة البيانات.

## 6. قاعدة البيانات وسلامة البيانات

- القاعدة المحلية الحالية تحتوي 46 جدولاً؛ لا تعِد تشغيل `GroceryPOS_Database.sql` كطريقة ترقية. السكربت ينشئ مخططاً أولياً ويتوقف إذا وجد الجداول.
- قبل أي تغيير في الإنتاج: خذ نسخة احتياطية، اكتب سكربت ترقية مستقلاً قابلاً للمراجعة، واختبره على نسخة من القاعدة، ثم تحقّق من النتيجة وخطة الرجوع.
- لا تنفّذ عمليات `DROP` أو إعادة إنشاء أو حذف شامل على قاعدة بيانات موجودة دون موافقة صريحة ونسخة احتياطية متحققة.
- تحقق من التطابق بين الرصيد المخزن والدفتر عبر `vw_CustomerBalanceCheck` و`vw_SupplierBalanceCheck`. المتوقع ألا تعيدا صفوفاً.
- تحقق من عد الجداول عند الحاجة:

```sql
SELECT COUNT(*) AS TableCount
FROM sys.tables
WHERE schema_id = SCHEMA_ID(N'dbo');
```

- فحوص القراءة الأولية للمخزون تتم عبر `vw_ProductStock`. مصدر الكمية هو الدفعات؛ لا تعدّل الرصيد المخزن مباشرةً لتصحيح فرق.

## 7. الأمان والتشغيل

- خوارزمية كلمات المرور الحالية PBKDF2-HMAC-SHA256 مع 600,000 دورة وSalt عشوائي 32 بايت وناتج 32 بايت. عند تعديلها، حافظ على توافق كلمات المرور المخزنة أو أضف ترقية آمنة بعد التحقق.
- الحساب الأول يمنح دور المالك داخل معاملة واحدة؛ لا تنشئ مستخدم مالك افتراضياً في SQL ولا تضع كلمة مروره في ملفات المشروع.
- إعدادات قفل الدخول الحالية في `Settings`: `MaxFailedLogins` و`LockoutMinutes`. افتراضات قاعدة البيانات 5 محاولات و15 دقيقة.
- سجل التطبيق:

```text
%LOCALAPPDATA%\GroceryPOS\logs\application.log
```

لا تسجل كلمات مرور أو بيانات اعتماد. راجع الصلاحيات على مجلد السجل عند ظهور رسالة فشل كتابته.
- تكامل Windows الحالي مخصص للتطوير المحلي. لا توزّع قاعدة SQL بصلاحية `sa` ولا تمنح أجهزة الكاشير صلاحيات إدارية.

## 8. قائمة تحقق لاختبار تغييرات الكتالوج

1. بناء Debug وRelease دون أخطاء أو تحذيرات.
2. فتح الكتالوج بصلاحية العرض فقط والتأكد من غياب أزرار الإضافة والتعديل.
3. البحث بالاسم وSKU والباركود.
4. إنشاء منتج باسم عربي، وسعر، وباركود، وحد أدنى، وتتبع صلاحية.
5. رفض الاسم الفارغ، والقيم السالبة، ورمز SKU أو باركود مكرر.
6. تعديل المنتج والتحقق من تحديث `UpdatedAt` و`UpdatedBy` و`AuditLogs`.
7. تعطيل المنتج والتأكد من بقائه في قاعدة البيانات وعدم ظهوره كنشط.
8. محاولة تغيير الوحدة الأساسية لمنتج موجود والتأكد من رفضها.
9. إنشاء تصنيف فرعي ومنع تكرار الاسم ضمن المستوى نفسه، ومنع إنشاء حلقة في شجرة التصنيفات.
10. منع تعطيل تصنيف رئيسي ما دام لديه تصنيف فرعي نشط، ومنع تفعيل ابن إذا كان أبوه غير نشط.
11. إضافة وحدة تحويل واختبار معامل التحويل والباركود الفريد والسعر ووحدة البيع الافتراضية.
12. رفض باركود مستخدم لوحدة أخرى، أو تكرار وحدة داخل المنتج، أو تعطيل الوحدة الأساسية للمنتج النشط.
13. التأكد أن المستخدم دون `Products.EditPrice` لا يستطيع تغيير أسعار المنتج أو الوحدات حتى باستدعاء الخدمة مباشرة.
14. التحقق من طلب تغيير كلمة المرور المؤقتة قبل فتح لوحة التحكم.
15. اختبار تغيير كلمة المرور الحالية بكلمة صحيحة، ورفض كلمة حالية خاطئة، ورفض إعادة استخدام الكلمة نفسها.
16. اختبار إعادة التعيين بصلاحية `Users.Manage` ورفضها دون الصلاحية، ثم التأكد من فرض التغيير في الدخول التالي.
17. التأكد أن سجل التدقيق لا يحتوي كلمة المرور أو قيمة الـSalt أو التجزئة.
18. انقطاع SQL أو تعذر الاتصال: ظهور رسالة مفهومة دون حفظ جزئي.

لا تُنفّذ اختبارات الإدخال على قاعدة تحوي بيانات مستخدمين فعلية؛ استخدم قاعدة تطوير وبيانات اختبار معلّمة.

## 9. استكشاف الأخطاء

| العَرَض | ما يجب فحصه |
|---|---|
| فشل `GenerateResource` في البناء | استخدم خيار x64 في أوامر البناء أعلاه، وتحقق من تثبيت .NET Framework 4.8 targeting pack. |
| خطأ اتصال عند بدء التطبيق | حالة خدمة SQL Server، اسم الخادم في `App.config`، اختيار قاعدة `GroceryPOS`، وصلاحيات حساب Windows. |
| التطبيق يطلب إعداد المالك رغم وجود مستخدمين متوقعين | تحقق من قاعدة البيانات التي يشير إليها `App.config` وعدد المستخدمين في `dbo.Users`. |
| التصنيفات أو الوحدات غير متاحة | تحقق من وجود صفوف نشطة في `dbo.Categories` و`dbo.Units`. |
| رفض SKU أو باركود عند الحفظ | تحقق من الفهارس الفريدة `UX_Products_Sku` و`UX_ProductUnits_Barcode`. |
| مشكلة بعد تغيير مخطط SQL | قارن أسماء الأعمدة والقيود مع سكربت SQL، وراجع سجل التطبيق؛ لا تعد تشغيل سكربت الإنشاء على قاعدة قائمة. |

## 10. تحديث هذا الدليل

عند إضافة وحدة أو تغيير قرار بيانات:

- حدّث نطاق التنفيذ والقرارات في [`System-Overview.md`](./System-Overview.md).
- أضف في هذا الملف المسؤوليات الجديدة وخطوات البناء والاختبار والاستعادة المناسبة.
- أبقِ سكربتات الترقية منفصلة عن سكربت الإنشاء الأولي.
- سجّل ما اختُبر فعلاً وما بقي غير منفذ؛ لا تصف الميزة بأنها مكتملة اعتماداً على نجاح البناء وحده.
